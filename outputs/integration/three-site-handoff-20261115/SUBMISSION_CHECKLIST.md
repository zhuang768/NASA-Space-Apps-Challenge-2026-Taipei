# 提交流程驗收｜不是正式提交內容

- [NASA 2026 官方日程](https://www.spaceappschallenge.org/2026/)：台北場當地時間 **11/15 23:59（Asia/Taipei）** 截止。
- [官方指南](https://www.spaceappschallenge.org/resources/project-submission-guide/)；[主辦方說明：Demo 與 Final Project 是不同欄位](https://github.com/nasa/spaceapps/discussions/1991)。用登出的視窗檢查兩個最終連結。**本資料包不是 Demo**，示範材料仍應由團隊確認／製作（最多 7 頁簡報或 30 秒影片；英文或英文字幕依官方指南／Navigator）。
- 要交的研究版本：只交實際可證明的部分。目標名、三處中心座標、佐證文件版本及網站部署指紋必須一致。不要拿仍在線上的舊 Worker 版本充當三點最新成果。
- [賽題](https://www.spaceappschallenge.org/2026/challenges/permanent-moon-base-locations-and-mars/) 要求辨識並描寫**新的地球類比**，以地圖／視覺化／工具呈現。UV、Haughton、Beacon 等有先例；如現有成果僅足以說「已知場址的限定方法參照」，請如實標記，不能稱三組新址或已經驗證。火星限定範圍是否符合本隊報名的賽題解讀，沒有團隊或主辦當次的同意紀錄可確認。
- 原始資料的署名、修改註記與第三方條款跟著衍生圖表（含使用的 Montabone 衍生資料）；[NASA 官方條款](https://www.spaceappschallenge.org/legal/)。不要把未取得再發布權的檔案、非公開原始資料、帳戶資訊或未成年身分放進公開版。私有 repo 不必為此整庫公開。
- 最後在 NASA 團隊頁 **Project → Submit**，保留 Submitted 狀態或官方回執；GitHub branch、部署成功或 Save 不是提交。沒有找到回執，尚未代替隊伍送出。
