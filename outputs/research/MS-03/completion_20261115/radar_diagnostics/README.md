# MS-03 雷達自動峰值與尺度校核

基準為 `234e58a8a0a0a9966e97e1b13d7ccc587cf3e8aa`。本補充使用既有 S_04624502_RGRAM 的原像素匯出，不取代原始雷達、模型或前輪判讀。65個格內中心、2016-06-07T22:23:51.611–22:24:01.059 UTC；中心在格內不代表全部散射足跡都在格內。

## 實際解答的問題

**現有裁切能否直接以每column最大功率當地下界面？沒有這項依據。** [逐列結果](radar_pick_diagnostic.csv)顯示，最大功率位置相對模型nadir為−67至+185個採樣，中位−29；43個在模型nadir之前、22個之後、0個正好一致。64個相鄰column對的最大位置變化為−202至+207採樣，其中10對絕對變化超過100採樣。所有最大值均不在這個裁切的首末row。這個結果排除「只看裁切邊界即可放心採用argmax」的做法，並不指出真正成因。

模型自身最大值相對模型nadir為−1至+4採樣；這是模型內部相容性的描述，不能將模型升為獨立表面真值。10及100採樣是公開列出的描述門檻，並非自動檢出準則。原始最大值、正負時間差、模型差異全部保留，未平滑、校時、挑選回波或轉成局部深度。

**37.5ns採樣是否能獨立驗證約0.10m熱模型界面？不能由採樣間距作此主張。** 官方處理說明§1的10MHz頻寬約為15m真空單程解析尺度；37.5ns採樣對應5.621m真空單程距離，兩者定義不同。[range_support.csv](range_support.csv)按標準均勻介質公式重算：Δr=c/(2B√εr)、Δr_sample=cΔt/(2√εr)。εr=3.15僅是文獻純水冰示例，非MS-03實測；其理想頻寬尺度8.446m，而0.10m的雙程時間1.184ns，只有0.0316個採樣。這不建立校準檢出極限，也不表示薄層絕對不能影響合成回波；只說現有未經驗證的獨立反射層pick，不能支撐0.10m界面深度驗證。

## 資料與不可推論事項

- NPZ是前輪從原始bytes取得的269×65功率表，原始row2182–2450、column2185–2249。SHA256固定為 `ac36e98d8af635bf1078ac7689005e490b09f2d765a7e60aa170a24b266c095c`；原bytes與範圍計畫仍在 `../../local_validation/gap_completion/`。
- 本輪讀回原PDS雷達LBL與simulation XML，保留原檔checksum於來源表；雷達LBL宣告3600×3575個PC_REAL 32-bit功率。其處理參數在註解內，不把它們當作此次執行已驗證設定。
- 官方處理說明§1、§2.3說明旁瓣、電離層校正及取捨；這些是可能的影響來源，不據此指認本格異常根因。本輪沒有從圖形推定哪一項已發生。
- 不作觀測功率減模型功率；不估局部介電常數、冰量、冰深、校準SNR或檢出率；不從無可信pick推無冰。
- CRISM的已知處理階段非等價與實際run缺件沿用既有 `production_history/`、`t1811_run_artifacts/`。任意擬合delivered AL與SU不能還原執行，也不能代替雲霜／儀器QA，因此不產生擬合校正或冰閾值。

## 重現

從專案根目錄執行 `python3 outputs/research/MS-03/completion_20261115/radar_diagnostics/analyze.py`；或用 `--input` 指向固定NPZ。只需NumPy。程式保留所有65列，重算最大值與尺度，並以獨立的逐元素搜尋覆核全部最大值；來源輸入前後hash相同。[validation.json](validation.json)的9項通過只支持重算與資料完整性，不代表地下冰驗證。

圖表如需重畫，執行同目錄 `plot.py`。本輪增加的是自動峰值方法的定量適用性評估；實際表面定位、可信地下反射層、介電反演、冰存在與含量、雲霜及光譜run歸因仍未解決。
